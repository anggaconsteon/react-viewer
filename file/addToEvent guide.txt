==========================================================
addToEvent — GUIDE (v0.2)
==========================================================

PATTERN: keyed (char-code) sibling dari addToTable.
TUJUAN:  insert dokumen baru ke event ledger (append-only)
         setiap aksi user (submit patroli, lapor incident,
         clock-in/out, request, dsb) → 1 row event baru.

NOTASI INHERITED dari addToTable:
  <N>  = numeric field target (TIDAK dipakai di addToEvent)
  ⬤   = boundary kiri/kanan
  ◀ ▶ = data sebelah KIRI (system stream — timestamp, dsb)
  ◁ ▷ = data sebelah KANAN (user input — form field N)
  ◆   = pemisah multi-doc (jika insert >1 doc)
  ★   = pemisah multi-entry di kanan
  ◼   = pemisah antara field-name dan value
  ⭘   = penanda awal field
  N|T7|format
       = N (index), T7 (timezone Asia/Jakarta UTC+7),
         format (date format spec)

==========================================================
PERBEDAAN UTAMA vs addToTable
==========================================================

addToTable  : positional. Field name = <N> urut posisi 1..N.
              Wajib lengkap dari <1> sampai <N>. Sparse tidak
              didukung — field kosong tetap counted.

addToEvent  : KEYED. Field name = char-code semantik (ty, t,
              cv, dst). Order BEBAS. Sparse-by-default —
              kalau field tidak di-define, berarti kosong/
              NULL (TIDAK perlu placeholder).

              CONSEQUENCE:
              - Tidak perlu hitung posisi
              - Tambah/kurang field tanpa shift index
              - Parser baca by key, bukan posisi

==========================================================
ATURAN RINGKAS
==========================================================

1. Required: r, ty, t, ts. Wajib ada di tiap doc.
2. Order BEBAS (parser keyed) — tapi konvensi: r → tablevid →
   metadata → ty/t/ts → content fields.
3. Omit field = NULL. JANGAN tulis `⭘fc◼` kalau memang
   kosong — cukup tidak menulis baris itu sama sekali.
4. APPEND-ONLY: tidak ada update/delete variant. Kalau perlu
   mutasi state, pakai updateTableRow (DSL terpisah) untuk
   tabel state, dan tetap append event baru pakai addToEvent
   dengan `rf` ke event asal.
5. Multi-doc insert pakai `◆` antar blok.
6. Char-code unique secara global: `sv` di route = `sv` di
   event content = site VID. `st` di workforce konteks =
   status. `t` reserved buat timestamp — task pakai `ta`.

==========================================================
CHEAT SHEET — TOKEN
==========================================================

◀N|T7|epoch▶              system stream, epoch ms
◀N|T7|Ddd MMM yyyy HH:mm▶ system stream, formatted
◁N▷                       form field N (raw user input)
◁N|T7|format▷             form field N formatted
literal-value             baked static value
%timeReceived%            replaced from spreadsheet context
<no_request>              system-injected ref id (rf field).
                          Sama mekanisme dgn addToTable.
                          New submit → sistem generate baru.
                          Detail page / approval → sistem
                          inject dari parent context.
                          Author bebas pakai placeholder
                          ini ATAU ◁N▷ ATAU literal.
