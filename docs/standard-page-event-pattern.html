1. Konsep Dasar

Ketika user menekan tombol submit di form:

[ User klik Submit ]
        │
        ▼
action: "savesend"
        │
  ┌─────┴─────┐
  ▼           ▼
Event C     addToTable
→ tab Event   → Firebase
(audit trail) (data operasional)
dari POSITION dari DSL string
Event C dan addToTable adalah 2 hal TERPISAH:
• Event C = dari position widget form (★ sections)
• addToTable = dari DSL string di property addToTable pada button

2.2 Default Block (<1> s/d <12>) — WAJIB SAMA

Bagian ini HARUS IDENTIK di semua page. Jangan ubah urutan atau index-nya.
IndexIsiCell ReferenceKeterangan
<1>◁17▷— (runtime)No. Permohonan — NUMBER widget pos 17
<2>Status awal— (static)PENDING, MENUNGGU, dll
<3>[]— (static)History — placeholder
<4>[] atau [[...]]— (static)Approval — [] jika tanpa approval
<5>myVIDSettings!$B$1VID user yang submit
<6>myNameSettings!$B$2Nama user yang submit
<7>siteVID'op1'!$K$8VID site/lokasi kerja
<8>siteName'op1'!$L$8Nama site
<9>siteVID2'op1'!$K$7VID group/organisasi
<10>siteName2'op1'!$L$7Nama group
<11>submitTime◀2|T"&System!$B$3&"|...▶Timestamp formatted
<12>submitEpoch◀2▶Timestamp raw (epoch ms)
Kenapa <3> dan <4> wajib meskipun kosong?
• <5> (VID) selalu di index 5 di SEMUA page
• op1Script bisa pakai 1 scaffold D formula
• Kalau nanti butuh approval, tinggal isi <4> — zero migration

2.3 Tail Block (<13>+) — CUSTOM per page

Mulai dari <13>, isi dengan data form sesuai kebutuhan page.

TokenArtiContoh
◁N▷Value dari widget di position N◁5▷ = datePicker pos 5
◀N▶System stream value◀2▶ = epoch timestamp
◀N|T7|format▶System stream + format waktu◀2|T7|Ddd MMM yyyy HH:mm▶
◁N|T7|format▷Widget value + format waktu◁6|T7|Ddd MMM yyyy▷

5. D Formula (op1Script)

5.1 Struktur: Scaffold + Tail

=REGEXREPLACE(
  {SCAFFOLD} & "◻" & {ORG_CHAIN} & "◻" & {ROUTE} & "◻" & {TAIL}
, "(""|')", "`")
BagianFormulaStatus
Scaffold C$16&"◼"&D$16&"◼"&B$16&"◼"&$F$13&"◼"&N$14&", "&M$14&", "&L$14&", "&K$14&", "&J$14&", "&I$14 SAMA semua route
Org chain 'op1'!$H$1&"☆"&'op1'!$H$2&"◻"&'op1'!$I$5&"◻"&'op1'!$J$5&"◻"&'op1'!$K$5 SAMA semua route
Route block Event!$B$2&"☆"&$B$12 SAMA semua route
Tail ${CELL}$13&"☆"&${CELL}$13&... BEDA per route

5.2 Cara Menentukan Tail

  1. List semua position yang punya data di form
  2. Convert position → op1Script column (tabel Section 3.3)
  3. Susun cell references dengan separator ☆
  4. SKIP F13 — sudah masuk di scaffold
  5. SKIP position kosong

8. Checklist: Membuat Page Baru

A. Persiapan

  • Tentukan module name dan table path Firebase
  • Tentukan flag name
  • Tentukan apakah butuh approval (berapa level?)
  • List semua field form dan assign position (3-16, 18+)
  • Position 17 = auto-number (NUMBER) — WAJIB
  • Position 251 = submit button — WAJIB

B. addToTable

  • Copy template dari Section 2.5
  • Ganti placeholder
  • Default block <1> s/d <12> — JANGAN UBAH cell references
  • <3>◼[] dan <4>◼[] (atau approval array) — WAJIB ADA
  • Tail dari <13> dst — map ◁N▷ ke position widget
  • <30> — summary template untuk display
  • index — minimal 1★S◼2★S◼5★N◼7★N◼9★N

C. Button Config

  • action: "savesend" (BUKAN "addToTable")
  • flag: "{flag_name}"
  • gpsPosition: 2
  • com: "auz"
  • run include 17:generate_number◆251:disable
  • addToTable = DSL string dari step B
  • chain = DO_DIALOG konfirmasi

D. Event & Reporting

  • Pastikan flag terdaftar di sistem
  • Map position → ★ → op1Script column
  • Buat D formula: scaffold + org + route + tail
  • Tambah row di op1Script
  • Test: submit form, cek Firebase + Event tab

E. Verifikasi

  • Firebase <1> s/d <12> benar
  • <5> = VID user (bukan hardcoded)
  • Event tab punya row baru
  • D formula tanpa #VALUE! atau #REF!
