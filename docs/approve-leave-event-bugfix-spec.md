## Context

When an approver clicks Approve/Reject, the app creates an Event with flag `approve-leave`. The current implementation has 8 bugs in how the Event C data is constructed. This spec defines the EXACT correct output.

## Bug List (8 bugs)

### Bug 1: ★1 identity block is EMPTY

**Current:** `⬤★★Cuti Besar...` (★1 is empty)

**Fix:** ★1 MUST contain the approver's identity block. This is auto-generated by the system for normal `savesend` events. For approve-leave, the identity block must be the person performing the approval action — their VID, name, email, and org chain, separated by `☆`.

```
★{approverVID}☆{approverName}☆{email}☆☆☆{siteName}☆{siteVID}☆{orgChain}★
```

### Bug 2: Jenis Cuti appears TWICE (★2 AND ★3)

**Current:** `★Cuti Besar ★Cuti Besar★`

**Fix:** ★2 should be Photo URL (from Firebase `<15>`), NOT Jenis Cuti. Jenis Cuti goes in ★3 ONLY.

```
Before: ★Cuti Besar ★Cuti Besar★
After:  ★{photo_url}★Cuti Besar★
```

**Root cause:** Code is writing `<13>` (Jenis Cuti) to BOTH ★2 and ★3. Change ★2 to read from `<15>` instead.

### Bug 3: Photo URL is at ★9 instead of ★2

**Current:** ★9 = `https://firebasestorage...jpg`

**Fix:** Photo URL must be at ★2 (position 3). ★9 (position 10) should contain Keterangan from Firebase `<14>`.

```
★2  = record.<15>   (Photo URL)     ← move here
★9  = record.<14>   (Keterangan)    ← currently has photo, replace with keterangan
```

### Bug 4: Replacement VID missing at ★15

**Current:** ★15 is empty

**Fix:** Read Firebase `<22>` and put it at ★15.

```
★15 = record.<22>   (Replacement VID)
```

### Bug 5: Replacement Name missing at ★17

**Current:** ★17 is empty

**Fix:** Read Firebase `<23>` and put it at ★17.

```
★17 = record.<23>   (Replacement Name)
```

### Bug 6: Approver VID and Name are in SEPARATE ★ sections

**Current:** `★87544551624342★Agenia Demo-7★` (two ★ sections)

**Fix:** Combine into ONE ★ section at ★18, separated by `☆`:

```
Before: ★87544551624342★Agenia Demo-7★
After:  ★87544551624342☆Agenia Demo-7★
```

This means ★18 = `{approverVID}☆{approverName}` and ★19 becomes empty (freed up).

### Bug 7: Level 1 block uses ◇ separator instead of ☆

**Current:** `1◇APPROVED◇Muhamad Angga◇85924392055168◇21 May 2026 15:26◇1779352003642`

**Fix:** Replace ALL `◇` with `☆` inside level blocks:

```
Before: 1◇APPROVED◇Muhamad Angga◇85924392055168◇21 May 2026 15:26◇1779352003642
After:  1☆APPROVED☆Muhamad Angga☆85924392055168☆21 May 2026 15:26☆1779352003642
```

### Bug 8: Level 2 block uses ◇ separator instead of ☆

Same fix as Bug 7:

```
Before: 2◇APPROVED◇Agenia Demo-7◇87544551624342◇21 May 2026 15:43◇1779353014253
After:  2☆APPROVED☆Agenia Demo-7☆87544551624342☆21 May 2026 15:43☆1779353014253
```

**Rule:** ALL level blocks (1 through 5) must use `☆` as the internal separator. Never `◇`.

## Level Block Format

Each level block at ★23-★27 is a `☆`-delimited string:

```
{level_number}☆{status}☆{approver_name}☆{approver_vid}☆{timestamp_formatted}☆{epoch_ms}
```

| Field | Type | Example |
|-------|------|---------|
| level_number | int | `1`, `2`, `3` |
| status | string | `APPROVED` or `REJECTED` |
| approver_name | string | `Muhamad Angga` |
| approver_vid | string | `85924392055168` |
| timestamp_formatted | string | `21 May 2026 15:26` |
| epoch_ms | string | `1779352003642` |

**CRITICAL:** Use `☆` separator, NOT `◇`.

**CRITICAL:** Levels are CUMULATIVE. When Level 2 approves, the Event must contain BOTH Level 1 data AND Level 2 data. Read all levels from the UPDATED `<4>` array.

Empty/pending levels = empty ★ section.


Example: `87544551624342☆Agenia Demo-7`

Do NOT split into two separate ★ sections.

## Implementation Pseudocode

```
function buildApproveLeaveEventC(record, approver, geoData) {
    // 1. Build geo block (same as any savesend)
    geoBlock = "0approve-leave◆" + timestamp + "◆◆◆" + lat + "◆" + lng + "◆◆" + country + "◆" + zip + "◆" + state + "◆" + regency + "◆" + district + "◆" + village + "◆" + street + "◆" + number + "◆" + locationType

    // 2. Build ★ sections
    sections = new Array(28).fill("")  // ★1 through ★27, index 0 unused

    // ★1 = identity (auto from system, approver's identity)
    sections[1] = approver.vid + "☆" + approver.name + "☆" + approver.email + "☆☆☆" + approver.siteName + "☆" + approver.siteVID + "☆" + approver.orgChain

    // ★2-★17 = request data from Firebase record
    sections[2]  = record["<15>"]   // Photo URL
    sections[3]  = record["<13>"]   // Jenis Cuti
    // sections[4] = empty (position 5 unused)
    sections[5]  = record["<16>"]   // Tanggal Mulai (epoch)
    sections[6]  = record["<18>"]   // Tanggal Selesai (epoch)
    // sections[7], [8] = empty
    sections[9]  = record["<14>"]   // Keterangan
    sections[10] = record["<20>"]   // Jumlah Hari
    // sections[11]-[13] = empty
    sections[14] = record["<2>"]    // Overall Status (AFTER updateTableRow!)
    sections[15] = record["<22>"]   // Replacement VID
    sections[16] = record["<1>"]    // Request Number
    sections[17] = record["<23>"]   // Replacement Name

    // ★18 = approver identity (COMBINED with ☆)
    sections[18] = approver.vid + "☆" + approver.name

    // ★19-★22 = empty (reserved)

    // ★23-★27 = approval levels from <4> array
    approvalLevels = record["<4>"]  // array of arrays
    for (i = 0; i < approvalLevels.length && i < 5; i++) {
        level = approvalLevels[i]
        // level = [levelNum, status, vid, name, timestamp, epoch]
        if (level[1] != "PENDING" && level[1] != "") {
            // Use ☆ separator, NOT ◇
            sections[23 + i] = level[0] + "☆" + level[1] + "☆" + level[3] + "☆" + level[2] + "☆" + level[4] + "☆" + level[5]
        }
        // else: leave empty for pending/unfilled levels
    }

    // 3. Assemble
    eventC = geoBlock + "⬤"
    for (i = 1; i <= 27; i++) {
        eventC += "★" + sections[i]
    }

    return eventC
}
```

**Notes on the pseudocode:**
- `record["<4>"]` is the approval levels array. Each entry: `[level_number, status, approver_vid, approver_name, timestamp_formatted, epoch_ms]`
- The order in the level block output is: `level☆status☆NAME☆VID☆timestamp☆epoch` (name before vid)
- Only include levels that have been acted on (status != PENDING and not empty)
- Read `record["<2>"]` AFTER `updateTableRow` completes to get the correct status
